# 양정베스트안과 관리자

사용자가 제공한 `admin-system-reference.md`의 공통 진입점, 비공개 설정, 서버 인증, CSRF, 파일 내용 검사, 검색 제외 원칙을 현재 Vercel Node.js · Supabase 환경에 적용했습니다. PHP·MySQL·FTP·.htaccess 파일을 배포하지 않습니다.

## 화면과 동작

- `/admin/`: 실제 저장된 게시글 수와 최근 수정한 글. 방문자 통계를 추정하거나 임의로 생성하지 않습니다.
- `/admin/posts/`: 제목·본문·작성자·태그 검색, 주제·상태 필터, 12개씩 페이지 구분.
- `/admin/new/`, `/admin/edit/:id/`: 기존 작성·의료 검수·발행 규칙을 유지하는 편집기.
- `/admin/preview/:id/`: 인증된 관리자만 저장된 초안도 미리 볼 수 있습니다.
- `/admin/settings/`: 연결 상태와 운영 안내. 자격증명은 표시하지 않습니다.
- `/api/posts/status`: 보관 또는 보관된 글의 초안 복원만 허용합니다. 이 경로로 직접 발행할 수 없습니다.

보관은 복구 가능한 공개 중단입니다. 영구 삭제 기능은 제공하지 않습니다. 의료정보를 수정해 발행할 때 검수 완료를 다시 확인해야 합니다. 초안 복원은 기존 검수 승인을 해제합니다.

글쓰기의 ‘질문과 참고자료’ 구역(FAQ·별도 참고자료·태그 입력)은 소유자 요청으로 제거했습니다. 기존 글을 수정해도 저장된 FAQ·출처·태그는 보존하며 새 글에는 빈 값으로 둡니다. 별도 출처 입력은 발행 필수 조건에서 제외하고 실제 의료 검수자·검수일·검수 승인은 계속 확인합니다.

## 인증과 요청 보호

`src/admin-auth.js`가 Vercel의 모든 `/admin/` 화면과 `/api/` 요청을 먼저 검사합니다. 서버가 인증한 컨텍스트만 앱에 전달합니다. 브라우저의 인증 흉내 헤더나 예전 Basic 인증으로 우회할 수 없습니다.

기존 서버 환경변수 `ADMIN_USERNAME`(기본 admin), `ADMIN_PASSWORD`를 그대로 사용합니다. 소유자 1계정 운영 모델이며 별도 계정 생성이나 기본 비밀번호를 추가하지 않습니다. 복수 계정·MASTER 권한 편집 기능이 없으므로 마지막 MASTER 잠금 문제도 발생하지 않습니다. 복수 계정이 필요해지면 Supabase Auth와 계정 권한·비활성 상태 조회를 도입해야 합니다.

- HTTPS 전용 `__Host-yjbest_admin_session` 쿠키: HttpOnly, Secure, SameSite=Lax, Path=/, 최대 8시간.
- 서버 비밀로 서명한 세션. 로그인마다 새 무작위 값을 발급합니다. 로그인 전 CSRF 쿠키와 인증 세션의 용도를 구분합니다.
- 서버의 현재 계정 설정으로 요청마다 서명을 확인합니다. 계정/비밀번호 변경 후 재배포하면 기존 세션은 모두 거부됩니다.
- 로그인 실패는 아이디의 존재 여부를 구별하지 않는 같은 문구를 반환합니다. 로그인 폼에도 짧은 수명의 CSRF 토큰이 있습니다.
- 게시글 저장·상태 변경·로그아웃은 모두 POST, 같은 Origin과 세션에 결합한 CSRF 토큰을 확인합니다.
- 로그아웃은 현재 브라우저의 쿠키를 만료시킵니다. 서버에 세션 목록을 보관하지 않는 방식이므로 개별 세션 원격 폐기 기능은 없습니다. 전체 강제 만료는 비밀번호 변경 후 재배포로 처리합니다.
- 로그인 성공·실패 이벤트는 Vercel 서버 로그에 기록합니다. 아이디, 비밀번호, 토큰, 원문 IP는 이 이벤트에 기록하지 않습니다. 참고 문서의 DB `login_logs` 및 조회 화면은 이번 단일 계정 구성에 포함하지 않았습니다.
- 같은 실행 인스턴스에서 15분 이내 8회 실패하면 일시 제한합니다. 다중 인스턴스 전체의 시도 제한을 보장하는 기능은 아니므로 전체 제한이 필요하면 Vercel 방화벽이나 공유 저장소 기반 제한을 추가합니다.

로그인 자체는 게시글 DB 설정 전에도 표시됩니다. 관리자 기능은 저장소가 준비된 경우에만 동작하며, 임시 메모리 저장소로 성공을 가장하지 않습니다. 비밀 값은 `.env*`와 Vercel 환경변수에서만 관리합니다.

## 이미지

현재 본문은 HTML 화면 편집·HTML 코드 모드와 기존 Markdown을 지원합니다. 기본 문단 서식·링크·이미지·동영상 및 코드 모드의 표·접기 요소를 지원합니다. 화면 편집기가 표현하지 못하는 복잡한 표·접기는 HTML 코드 모드에서 저장합니다. 화면 모드로 열어보기만 하면 원문을 유지하고 실제 본문 서식을 편집한 경우 편집기 결과로 저장합니다.

서버에서 parse5로 HTML을 파싱한 뒤 허용한 요소와 속성만 다시 구성합니다. 스크립트, 이벤트 속성, SVG·MathML, 임의 iframe은 저장하지 않습니다. 동영상은 YouTube·Vimeo의 지정 플레이어와 HTTPS MP4·WebM 링크를 지원합니다. 동영상 파일을 DB에 직접 올리지는 않습니다.

본문 이미지는 선택 시 8MB 이하, 저장 시 장당 300KB 이하·최대 4장으로 압축합니다. 데이터는 게시글의 비공개 저장소에 두고 공개 HTML에는 `/media/:id/inline/:imageId` 주소만 넣습니다. 초안 이미지는 인증한 관리자만 열 수 있고, 발행 후 공개됩니다. 기존 질문·참고자료 입력 구역은 추가하지 않습니다. HTML 본문의 질문형 `<details><summary>`는 화면에 보이는 질문·답변과 같은 내용의 FAQ 구조화 데이터로 반영합니다.

선택 용량은 8MB 이하 JPG·PNG·WebP입니다. 브라우저에서 실제 디코딩 후 긴 변 1600px 이하, 저장 용량 500KB 이하로 재인코딩합니다. 서버는 저장 한도와 PNG/JPEG/WebP 매직 바이트를 다시 확인합니다. SVG·임의 HTML·PHP 텍스트는 이미지로 받지 않습니다.

이미지는 기존 게시글 데이터에 저장하고 서버가 안전한 Content-Type과 nosniff 헤더로 제공합니다. 업로드한 파일명을 서버 실행 경로로 사용하지 않습니다. 발행된 글의 대표이미지만 `/media/:id/cover`에서 공개하며 초안 이미지는 공개하지 않습니다.

## 배포와 확인

새 Supabase 테이블이나 추가 환경변수 없이 기존 `posts`와 서버 관리자 계정으로 동작합니다. `scripts/build-vercel.mjs`와 이전 Worker 자산 목록 모두 관리자 CSS·JS를 포함합니다.

관리자 HTML은 no-store, noindex,nofollow, 프레임 삽입 금지를 적용합니다. 공개 사이트의 robots·사이트맵에는 관리자 내부 화면을 포함하지 않습니다. 상담·팝업·멀티사이트 통계처럼 이번 홈페이지에 연결하지 않은 기능은 메뉴와 공개 API를 만들지 않았습니다.

검증: `npm test`, `npm run build:vercel`, `npm run build`, `npm run check`. 로컬 개발 서버는 루프백 주소에만 바인딩되며 관리자 인증을 생략하는 미리보기 모드입니다. 인터넷에 개발 서버를 노출하지 않습니다. 모바일 관리 화면은 `/__preview/mobile?screen=admin`에서 확인할 수 있습니다.

### 게시글 삭제

관리자 게시글 목록과 글 수정 화면에서 삭제 확인 화면으로 이동합니다. 복구 불가 확인란을 선택해야 삭제할 수 있으며, 서버는 로그인·동일 출처·CSRF와 삭제 확인값을 검증합니다. 삭제는 글 데이터와 그 안에 저장된 업로드 이미지를 함께 제거합니다. 보관·초안 복원은 별도로 유지됩니다. 방문자 페이지에는 관리자·글쓰기 링크를 표시하지 않습니다.
