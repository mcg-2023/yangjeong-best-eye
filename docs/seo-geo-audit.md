# SEO · GEO 개선 및 다음 작업

확인일: 2026-10-21. 로컬 코드에 반영했습니다. 실제 서비스 도메인과 검색 성과 데이터가 없어 검색 점수·순위·AI 인용률의 전후 수치는 산정하지 않았습니다. 테스트 통과 수는 SEO 점수가 아닙니다.

## 반영한 변경

| 항목 | 처리 |
| --- | --- |
| 대표 주소 | SITE_URL로 canonical·OG·JSON-LD·사이트맵·RSS 도메인 통일. 추적 매개변수는 대표 주소에서 제외 |
| 중복 주소 | /contact/ → /location/ 301, 지원 경로의 끝 슬래시 누락은 308. 제거한 의료진·진료분야 페이지는 404 유지 |
| 목록 | 2페이지 이상은 페이지별 canonical·제목. 범위 밖·잘못된 번호는 404. 검색 결과·실발행 글 없는 목록은 noindex |
| 글 공유 | 글별 OG article, 발행·수정 시간, 이미지·대체텍스트, Twitter 공유 카드 |
| 구조화 데이터 | 병원·웹사이트·페이지·글·경로 연결. 실제 본문에 표시한 작성자·검수일·참고자료·FAQ 사용. 진료시간의 점심 휴식 반영 |
| 이미지 | 별도 이미지 HTTP 주소와 캐시·지연 로딩. 공개 HTML에서 Base64 이미지 반복 삽입 제거. 미발행 이미지 주소는 404 |
| TEST 글 | 상세·이미지 noindex, 목록·슬라이드 data-nosnippet. 사이트맵·RSS 및 실제 글의 관련글에서 제외 |
| 미리보기 | 로컬·색인 중지 설정·대표 도메인과 다른 호스트는 noindex 메타 및 HTTP 헤더 |
| 검색 등록 | Google·네이버 소유확인 토큰 입력 설정 제공. 계정 연결은 미실행 |

의료진 소개 페이지·프로필은 추가하지 않았습니다. 기존 글 단위의 실제 작성·검수 표시만 유지합니다. 프리텐다드와 본문 최소 16px도 유지합니다.

## 설정

.env.example을 .env로 복사하면 로컬 서버에서 읽습니다. .env는 Git에서 제외됩니다. 배포 시에는 같은 이름의 런타임 환경변수를 설정해야 하며 빌드 파일에 자동 내장되지 않습니다.

| 환경변수 | 값 |
| --- | --- |
| SITE_URL | 실제 공개할 https://도메인 원점 주소. 경로·쿼리·계정정보 제외. 로컬에서는 빈 값 허용 |
| SITE_INDEXING | 검증 서버는 off. 공개 서비스는 on 또는 미설정. 로컬 미리보기는 항상 noindex |
| GOOGLE_SITE_VERIFICATION | Search Console에서 발급한 content 토큰만 입력 |
| NAVER_SITE_VERIFICATION | 네이버 서치어드바이저에서 발급한 content 토큰만 입력 |

소유확인 후 /sitemap.xml을 제출합니다. 네이버 RSS는 실제 발행 글이 최소 1개 생긴 뒤 /feed.xml을 제출합니다. TEST 글은 피드 항목으로 간주하지 않습니다.

## 추가 권장 사항 — 우선순위

1. **공개 도메인·검색 등록.** 도메인을 확정하고 소유확인·사이트맵 제출·URL 검사를 진행합니다. 기존 공식 홈페이지에서 저널로 HTML 링크를 연결해 발견 경로를 마련합니다. 외부 게시·계정 연결은 이번 로컬 변경에 포함하지 않았습니다.
2. **다섯 주제의 실제 검수 글.** 각 주제에 핵심 글을 하나씩 먼저 작성하는 것을 제안합니다. 기획 예시: ‘백내장 검사 전 준비할 사항’, ‘드림렌즈 검사에서 확인하는 항목’, ‘안구건조 검사 과정’, ‘망막검사 전 알아둘 점’, ‘녹내장 검사가 필요한 시점’. 이는 기획 예시이며 본문이나 진료 권고를 작성·발행한 것이 아닙니다. 병원의 실제 절차 확인과 의료 검수를 거쳐야 합니다.
3. **질문에 먼저 답하는 글.** 질문형 제목 → 짧은 핵심 답변 → 본문 소제목 → 실제 자주 묻는 질문 → 참고자료·검수일 순서를 권장합니다. 정해진 글자 수나 FAQ 개수보다 충분하고 정확한 답변이 우선입니다. 같은 내용을 지역명만 바꿔 여러 글로 만들지 않습니다.
4. **지역 정보 일치.** 홈페이지·기존 공식 홈페이지·네이버 플레이스·Google 비즈니스 프로필의 병원명·주소·전화·시간을 동일하게 유지합니다. 주차·공휴일 일정은 병원 확인 후 추가하면 방문 의도가 있는 독자에게 도움이 됩니다. 확인하지 않은 주차 정보는 생성하지 않았습니다.
5. **원본 사진·도표.** 실제 공간·검사 장비 사진과 설명 도표를 권리 확인 후 추가합니다. 사진 설명을 본문과 연결하고, 사례·수치는 병원이 확인한 자료와 출처를 사용합니다.
6. **공개 후 측정.** Search Console에서 색인 페이지 수, 노출·클릭·CTR, 지역+증상 검색어를 확인합니다. 모바일 Lighthouse와 실제 사용자 Core Web Vitals를 확인한 뒤 병목을 개선합니다. 현재 Lighthouse 점수와 실사용 성능은 측정하지 않았습니다. Google AI 기능 유입은 Search Console 웹 검색 성과에 합산되며 별도 GEO 점수로 표시되지 않습니다.

## 검증과 한계

- npm test: 게시판 및 도메인·메타·경로·페이지 이동·글 스키마·미발행 이미지 비노출 검증 11개 통과.
- npm run build: Worker 산출물 생성.
- npm run check: 빌드 앱의 내부 페이지·자산 27개, 제목 중복·설명·canonical·JSON-LD·사이트맵 색인 적합성·404 확인.
- 브라우저: 공개 HTML에 Base64 대표이미지가 없고, 현재 슬라이드와 목록 이미지가 새 주소로 로드되는 것 확인.

현재 로컬 TEST 글 3개만 있고 실제 의료정보 글은 없습니다. 기술적 준비만으로 검색 노출과 AI 인용 성과를 평가할 수 없습니다. 공개·검색 등록·실제 검수 글 발행 후 수집 결과를 확인해야 합니다.

## 공식 근거

- [Google AI 기능과 웹사이트](https://developers.google.com/search/docs/appearance/ai-features): 기본 SEO가 적용되며 별도 AI 파일·전용 스키마는 필수가 아님. 노출·색인은 보장되지 않음.
- [Google Article 구조화 데이터](https://developers.google.com/search/docs/appearance/structured-data/article): 글 제목·작성자·날짜·이미지의 의미 전달.
- [Google 유용하고 신뢰할 수 있는 콘텐츠](https://developers.google.com/search/docs/fundamentals/creating-helpful-content): 고유한 가치·명확한 출처·전문가 작성 또는 검수.
- [네이버 RSS 및 사이트맵 제출](https://searchadvisor.naver.com/guide/request-feed): 소유확인된 도메인 일치, RSS 실제 글 1개 이상 등 제출 조건.
