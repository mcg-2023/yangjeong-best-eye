# 양정베스트안과 · 건강정보

공식 로고의 네이비 `#213D78`, 차콜 `#414042`를 기준으로 만든 게시판형 홈페이지입니다. 기존 블로그 글을 연결하지 않습니다. 사용자 요청으로 작성한 TEST 게시글 3개를 로컬 게시판에서 확인할 수 있습니다.

## 실행

Node.js 24 이상에서 이 폴더를 열고 실행합니다.

```sh
npm ci
npm run dev
```

- 홈페이지: http://127.0.0.1:5173/
- 게시판 관리: http://127.0.0.1:5173/admin/
- 새 글 작성: http://127.0.0.1:5173/admin/new/

포트는 `PORT` 환경변수로 바꿀 수 있습니다. 로컬 서버는 127.0.0.1에만 바인딩하고 Host와 POST Origin을 검사합니다. 로컬 관리자 인증 생략은 로컬 서버의 환경 객체에만 적용되며, 배포 결과에는 포함되지 않습니다.

## 게시판 운영

1. 새 글 작성 → 주제·제목·본문 입력.
2. 임시저장 또는 검수 대기로 저장. 방문자 화면에는 표시되지 않습니다.
3. 의료정보는 핵심 답변·요약·작성자·검수자·검수일·참고자료를 입력하고 실제 의료 검수 완료를 확인한 후 발행합니다. 병원소식은 의료 검수 없이 발행할 수 있습니다.
4. 발행 후 수정할 때 의료 검수를 다시 확인합니다. 게시 중단·보관으로 공개 목록에서 내릴 수 있습니다.

본문은 Markdown의 제목(`##`, `###`), 굵게(`**`), 목록(`-`)을 지원합니다. Markdown 모드에서 입력한 HTML은 텍스트로 표시합니다. 대표이미지는 JPG/PNG/WebP, 최대 8MB를 선택할 수 있으며 브라우저에서 최대 1600px·500KB 이하로 줄여 저장합니다. 서버에서도 파일 내용을 검사합니다.

새 글은 HTML 화면 편집·코드 모드를 기본 제공합니다. 문단 서식, 링크, 본문 이미지 업로드(장당 300KB 이하로 자동 압축, 최대 4장), YouTube·Vimeo·HTTPS MP4/WebM 링크 삽입을 지원합니다. 서버가 허용한 HTML만 저장하며 JavaScript는 실행하지 않습니다. 기존 Markdown 글도 계속 편집할 수 있습니다. 본문 이미지까지 사용할 때 요청 한도는 3.5MB입니다. 자세한 내용은 `docs/admin-system.md`를 참고하세요.

## 저장과 백업

Vercel용 실행 설정을 추가했습니다. Vercel은 `npm run build:vercel`, Node.js 24.x와 `api/index.js`를 사용하고 게시글은 Supabase에 저장합니다. 연결 순서·환경변수·관리자 인증은 `docs/vercel-deployment.md`를 참고하세요. 기존 `npm run build`는 이전 Worker 출력용으로 유지합니다. 계정 연결과 저장소 환경변수는 별도로 실제 설정해야 합니다.

관리자 페이지는 `/admin/`입니다. 대시보드, 검색·주제·상태별 게시글 관리, 임시저장·검수·발행·보관·초안 복원, 미리보기, 운영 안내를 제공합니다. Vercel에 설정한 기존 관리자 계정을 사용합니다. 구조와 참고 문서 적용 범위는 [docs/admin-system.md](docs/admin-system.md)에 정리했습니다.

로컬 글은 `.data/journal.sqlite`에 실제 저장되며 재시작해도 유지됩니다. 로컬 DB는 Git과 배포 파일에서 제외합니다. 백업할 때 서버를 종료하고 `.data/journal.sqlite`를 복사하세요. 로컬 글이 배포 DB로 자동 업로드되지는 않습니다.

배포용 결과는 Cloudflare Worker ESM + Sites D1입니다. `.openai/hosting.json`에 `DB` 바인딩과 SQL 마이그레이션을 설정했습니다. Sites는 현재 소유자 전용이며 외부 저장·게시는 실행하지 못한 상태입니다. 외부 저장 승인 후 배포 및 D1 연동 검증이 별도로 필요합니다. 공개로 전환하려면 관리자 권한 모델을 먼저 추가해야 합니다. 현재 Worker의 관리 권한은 소유자 전용 Sites 접근 경계와 플랫폼 인증 헤더를 전제로 합니다.

## 검증과 빌드

```sh
npm test
npm run build
npm run check
```

`dist/server/index.js`는 서버 렌더링 앱과 최적화 이미지, CSS/JS가 포함된 독립 ESM Worker입니다. 검색엔진은 JavaScript 없이 본문·링크를 읽을 수 있습니다. 제목·설명·canonical·OG·JSON-LD·사이트맵·RSS를 서버에서 생성하며, 임시글·관리자·검색 결과·빈 주제는 검색에서 제외합니다. 새 글 발행은 재빌드 없이 목록·주제·관련글·사이트맵·RSS에 반영됩니다.

발행 글이 없는 초기 RSS는 빈 채널입니다. 첫 글 발행 후 RSS 항목이 생깁니다. GA4·Google Search Console·Naver Search Advisor는 계정 및 검증 코드가 없어 연결하지 않았습니다. 검색 순위나 AI 검색 인용을 보장하지 않습니다.

## 주요 파일

- `src/hospital.js`: 확인된 병원 정보와 주제
- `src/app.js`: 서버 라우팅, 저장·발행, SEO/RSS
- `src/views.js`: 홈페이지·게시판·편집기·글 상세 화면
- `src/content.js`: 의료 검수 조건·안전한 본문 렌더링
- `src/seo.js`: 대표 주소·공유 메타·글과 병원 구조화 데이터
- `src/style.css`: 초기화와 반응형 디자인
- `src/client.js`: 편집·이미지·미리보기 UI
- `drizzle/0000_posts.sql`: 데이터베이스 초기 스키마
- `docs/source-facts.md`: 정보 출처와 확인 상태
- `docs/launch-checklist.md`: 운영 전 확인 사항
- `docs/seo-geo-audit.md`: SEO·GEO 변경, 환경변수와 우선순위별 제안

첨부 명세의 콘텐츠·검색·검수 원칙을 반영하되, 기존 Vite 작업 환경을 유지하면서 Worker/SQLite 구조로 구현했습니다. Next.js/Payload/PostgreSQL은 설치하지 않았습니다. 대규모 권한 분리·예약발행·통계 수집·자동 콘텐츠 생성은 포함하지 않습니다.

폰트: Pretendard Variable v1.3.9를 웹사이트에 직접 포함합니다. 라이선스 원문은 `public/assets/Pretendard-LICENSE.txt`에 보관합니다. 본문·메뉴·폼의 최소 크기는 16px입니다.

의료진 소개는 병원안내 페이지 안에 사진·이름·전문의 표기·주요 경력으로 제공합니다. 홈 화면에는 의료진 소개를 표시하지 않습니다. 진료분야는 메인 화면의 요약 영역에서 안내합니다. 별도의 `/doctor/`, `/care/` 페이지와 상단 메뉴는 제공하지 않습니다. 진료분야 카드에서는 해당 주제의 게시글 목록으로 이동합니다.

2026-10-22 사용자 제공 폴더 `G:\내 드라이브\양정베스트안과`의 `_RAG` 요약과 디자인 원본을 참고했습니다. 병원안내에 실제 공간 사진 4개와 의료진 면허·전문의 자격 연도를 추가하고, 오시는 길에는 실제 안내 사진과 4층 접수·외래·검진 / 5층 수술센터 정보를 반영했습니다. 방문 FAQ와 검색용 FAQ 데이터도 동일한 층별 안내를 사용합니다.

## 최신 글 슬라이드와 테스트 글

홈 상단은 최신 발행 글 3개를 크게 표시하며 6초 간격으로 전환합니다. 700ms 페이드 전환과 이전·다음·자동 넘김 일시정지를 지원하며, 마우스를 올리거나 키보드로 조작하는 동안에는 자동 전환을 멈춥니다. 모션 감소 설정에서는 자동 전환을 시작하지 않고 페이드 효과를 생략합니다. 저널 사이드바를 제거하고 넓은 화면은 3열, 태블릿은 2열, 모바일은 1열로 게시글을 배치합니다.

`npm run seed:test`는 로컬 DB에 TEST 게시글 3개를 추가합니다. 같은 글이 이미 있으면 덮어쓰지 않습니다. 테스트 글은 관리 화면에서 수정·보관할 수 있고, 검색용 사이트맵과 RSS에서 제외되며 글 상세는 noindex입니다. 의료정보나 실제 병원 운영 공지로 작성하지 않았습니다.
